# TOEIC Study Notes

スマートフォン向けの非公式 TOEIC 学習教材です。オリジナルの Part 5 四択1問と、Part 7 の218語の英文メール・四択3問を収録しています。問題は本プロジェクト用に新規執筆し、ETS 公式問題の転載や近似改変は使用していません。

TOEIC は ETS の登録商標です。本教材は ETS の承認・推奨・提携を受けたものではありません。

**この変更はレビュー用です。GitHub Pages、Sites その他のホスティング設定や公開処理は含みません。**

## ローカルで確認する

必要環境：Python 3.12 以上、Git。外部 Python パッケージ・Node.js は不要です。

```sh
git fetch origin main
python3 scripts/registry.py
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 -m http.server 8000 --directory dist
```

`http://localhost:8000` を開きます。`dist/` は生成物で Git 管理対象外です（`.gitignore` で除外）。GitHub のソース ZIP に HTML は含まれないため、取得後に上記のビルドを実行してください。生成した HTML や CSS を `git add -f` で追跡対象に戻さないでください。デフォルトのビルドは「未公開の教材」と表示するプレビューです。公開先にアップロードしないでください。

`question-registry.json` が唯一の問題データ源です。HTML はビルド時に生成し、ブラウザーで JSON を取得する必要はありません。選択肢はネイティブのラジオボタンで、`label` 全体をタップできます。CSS `:has(input:checked)` により正誤・正解・日本語訳・根拠・誤答3つの理由を即座に表示します。JavaScript は一切使用せず、無効状態でも同じ操作ができます。

iPhone は Safari 15.4 以降など `:has()` 対応ブラウザーが必要です。本文は日本語16px・英文18px以上、選択肢は高さ58px以上で、拡大を禁止しません。キーボードでは Tab と矢印キーで回答できます。長文の全訳は折りたたみで常時参照でき、各設問には個別の訳と根拠も表示されます。回答は送信・保存しません。

## ファイル構成

```text
question-registry.json     問題・長文・解説・公開履歴・類似確認の台帳
styles.css                 モバイル対応と :has() による解説表示
scripts/registry.py        完全一致・類似・日付・欠損の検査
scripts/build.py           台帳検査後に dist/ を生成
tests/test_registry.py    不正データ・183日境界・出力のテスト
.github/workflows/check.yml 検証のみ。公開権限・デプロイ処理なし
```

## 台帳の編集

- `questions`: `id`, `part`, `passageId`, `prompt`, `options`（4択）, `answer`（0〜3）, `translation`, `optionTranslations`, `evidence`, `incorrectReasons`（正解以外の3添字）を保存します。
- `passages`: `id`, `title`, `text`, `translation` を保存します。英文は見出しも含め空白区切りで180〜250語を検査します。
- 問題・長文には `createdAt`（作成日）、`publishedAt`（最終公開日／未公開は `null`）、`publicationDates`（過去から順に全公開日／未公開は空配列）を保存します。日付は日本時間の `YYYY-MM-DD` です。
- `selection` で今回掲載する4問を指定します。Part 5 の1問と同じ長文を参照する Part 7 の3問が必要です。非掲載の過去問も削除しません。
- `historyComplete: true` は「全過去問と全公開履歴を照合済み」という運用上の宣言です。確認内容を `historyNote` に記載します。欠けた履歴を推測で埋めたり、検査を通すためだけに true にしないでください。不明なら false として公開を停止します。

初期リポジトリは README のみで、過去の教材・公開履歴はありませんでした。そのため今回の作成日を記録し、公開日はすべて未設定にしています。長文の日付も別に記録します。

既存 ID の本文・正解・長文参照・作成日は不変です。修正問題は新 ID で追加し、元の問題を保持してください。完全重複や軽微な改変は検査で拒否／要確認になります。解説の誤記は同じ ID で修正できますが、レビューしてください。

ビルドは `origin/main` の台帳と照合し、履歴項目の削除、公開履歴の書き換え、既存問題の改変を拒否します。基準台帳も検証します。基準に台帳がない場合、README だけの初期状態に限って新規作成を許可します。Git または基準ブランチを読めない場合も停止します。作業・公開前には必ず `git fetch origin main` で更新してください。

## 7時・12時の新規問題を共通台帳へ登録する運用

**7時・12時は日本時間（Asia/Tokyo）を想定した手動運用です。時刻に応じた問題生成、外部タスクからの取得、台帳への自動登録、定時の掲載切替・公開はすべて未実装です。** このリポジトリの Actions はテストとビルド検査だけで、定時実行設定はありません。外部で7時・12時に問題を作る場合も、自動でこのサイトや台帳へ反映されません。

登録先は時刻別のファイルではなく、常にリポジトリ直下の **`question-registry.json` 一つ**です。担当者が次の手順で統合してください。

1. 7時分・12時分の各登録前に `git fetch origin` を実行し、共通の作業ブランチを最新状態にします。登録作業は一人ずつ順番に行い、後の担当者は先の登録コミットを取り込んでから編集します。同じ古い台帳から別々に上書きしないでください。PR #1 が未マージの間は、その作業ブランチを登録先の基準とします。マージ後は最新の main から作業ブランチを作成します。
2. 各枠の問題文、4択、正解、長文、すべての訳・解説を確認します。問題・長文に未使用の ID を割り当てます。例：`p5-20261109-0700-01`、`p7-20261109-1200-01`、長文は `passage-20261109-1200-01`。時刻は識別のための命名規則であり、スケジューラーではありません。既存問題の再利用は新 ID にせず元の ID を使います。
3. 新規問題を `questions`、新規長文を `passages` の末尾に追記し、Part 7 の `passageId` を合わせます。既存の全問題・全履歴は残します。`createdAt` は実際の作成日、`publishedAt` は `null`、`publicationDates` は `[]` にします。**7時・12時に作成・受領しただけでは公開日を記録しません。** 既存 ID を使う場合は本文や過去の公開履歴を変更しません。
4. 今回受領した問題がすべて台帳に登録され、外部での過去の公開も含めて履歴が揃っているか確認し、確認内容を `historyNote` に追記します。不明点や欠落があれば `historyComplete` を `false` にして停止し、補完できるまで検査を通さないでください。
5. 次の検査を実行します。完全一致は登録不可です。類似問題は人が確認し、後述の `similarityReviews` に記録するまで保留します。

   ```sh
   python3 scripts/registry.py
   python3 -m unittest discover -s tests -v
   python3 scripts/build.py
   ```

6. 掲載する問題を切り替える場合だけ、`selection` を Part 5 の1問＋同じ長文を使う Part 7 の3問に更新し、再検査します。両時刻の問題は全て台帳に残し、一方を選択対象外にします。定時に切り替わる機能や、両枠の8問を同時に掲載する画面はありません。
7. 台帳変更だけをレビュー用 PR にコミット・push します。`dist/` は含めません。公開は別途承認を得た後に、下記の公開手順で実施します。再利用の場合は問題と参照長文のいずれも、直前の公開日から183日以上経過している必要があります。

CI の履歴比較は `origin/main` を基準とするため、未マージの追加問題同士の履歴保持は担当者の差分レビューでも確認してください。将来自動化する場合は、両時刻の処理を同じ台帳への直列更新にし、外部の既存公開履歴も取り込んでから検査する連携が必要です。現時点ではその連携も未実装です。

## 重複・類似・再利用の判定

```sh
python3 scripts/registry.py
# 必要なら別台帳／以前の台帳を指定
python3 scripts/registry.py --registry question-registry.json --baseline /path/to/previous-registry.json
```

検査対象は選択中の問題だけでなく、台帳に保持された全問題・全長文です。

1. Unicode NFKC・大小文字・句読点・空白を正規化して比較します。同一の問題文、または選択肢の順序を除いた問題全文の一致、長文の一致は**禁止**です。人の承認でも解除できません。
2. 正規化した問題文＋選択肢（長文は本文）を比較し、文字列の SequenceMatcher 類似度または単語集合の Jaccard 類似度が **0.72以上**なら**要確認**とし、未承認のままではビルドが失敗します。言い換えの意味的な一致を完全には検出できません。追加時は人が問題意図・題材・根拠も確認してください。
3. 再利用は同一 ID の `publicationDates` に追記します。**直前の公開日から183日以上**が必要です。182日は不可、183日は可です。同じ ID の問題を台帳に複製してはいけません。共通長文の再掲載にも同じ間隔を適用します。

類似判定の確認後、`similarityReviews` に以下の形式で記録します。検査エラーに対象 ID と必要な指紋が表示されます。指紋は本文変更時に無効になります。レビュー日も必須です。

```json
{
  "ids": ["辞書順で先のID", "辞書順で後のID"],
  "fingerprints": {"辞書順で先のID": "表示されたSHA256", "辞書順で後のID": "表示されたSHA256"},
  "reviewer": "実際の確認担当者",
  "reviewedAt": "2026-11-08",
  "reason": "何を比較し、なぜ別問題と判断したか"
}
```

ETS 問題のデータベースとの自動照合は行いません。公式問題を入力・参照して書き換える運用は避け、独立した執筆と人の確認を行ってください。類似承認は権利確認の代わりにはなりません。

## 将来、公開を承認されたときの手順

**現在は実行しません。** CI は検査のみで、main へのマージでも公開しません。

1. 最新の `origin/main` を取得し、欠損履歴や未確認の類似判定を解消します。
2. 今回の `selection` に含む問題と参照長文について、日本時間の公開当日を `publicationDates` の末尾に追記し、`publishedAt` に同じ日を設定します。初回は1日だけ記録します。既存履歴は残します。未来日は禁止です。
3. テスト後、次の**公開用ビルド**を実行します（実行当日の日付に置換）。当日の公開履歴が一つでも欠けていれば停止します。

   ```sh
   python3 scripts/build.py --release YYYY-MM-DD
   ```

4. 公開が別途許可された際に、この成功した `dist/` だけを公開処理に渡します。将来追加する公開ワークフローは、このビルド成功を必須条件にし、プレビュービルドの成果物を使用しないでください。
5. 実際の公開成功を確認し、台帳と同じコミットを保管します。公開に至らなかった当日の新規記録は、未公開扱いに戻して再検証します。公開済みの履歴は取り消しません。

検査失敗時は既存の `dist/` も削除し、古い生成物の誤公開を防ぎます。台帳の JSON 破損、必須項目欠損、不正な参照、無効な正解、重複、未承認類似、履歴不足、再利用違反はすべて非ゼロ終了です。これはリポジトリのビルド経路での停止設計です。手動コピーなどの別経路による公開や、リポジトリ外の未申告履歴は技術的には検知できません。

## ChatGPT生成問題の簡易登録（追加提案・未公開）

`python3 scripts/import_daily.py daily.json --output question-registry.updated.json` で、7時または12時の問題を共通台帳に**未公開のまま追記した候補ファイル**を作れます。`--select` を付けると4問をプレビュー対象に変更します。元の台帳は上書きしません。内容を確認してから台帳へ反映し、CIを通してください。

ChatGPTには次の形式の**JSONファイル**を出力させます。既存の `question-registry.json` の問題・長文と同じフィールドを持ち、外側は `{"slot":"0700","passages":[長文1件],"questions":[Part5 1件, Part7 3件]}` です。12時分は `slot` を `1200` にします。各IDは未使用、`createdAt` は実際の作成日（日本時間の登録日以前の有効な `YYYY-MM-DD`）、`publishedAt:null`、`publicationDates:[]` としてください。各設問の日本語訳・選択肢訳・根拠・不正解3つの理由も必須です。過去に作成した未公開問題も登録でき、作成日は登録日へ書き換えずそのまま保持します。未来日・存在しない日付・形式不正・作成日の欠損は拒否します。登録日（日本時間）は `historyNote` に別途記録します。

登録時には既存台帳と比較して重複・類似を検査し、問題があれば**ファイルを作らず停止**します。既存問題・履歴を削除しません。ChatGPTの定時タスクからGitHubへの自動転送は未実装です。iPhoneだけで使う場合は、定時タスクが生成したHTMLまたは問題JSONをこのチャットに添付し、台帳への変換・検査・レビュー用PR作成を依頼する運用もできます。PRの内容を確認するまでマージ・公開しないでください。
